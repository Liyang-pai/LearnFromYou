# 课堂截图上传

让现有 AI 学生同时读取教师讲解文字和对应截图，适用于试卷、PPT、教案及讲义截图。
这是手动截图输入，不是屏幕共享或原始文档解析。

## 使用

1. 创建试讲；也可以先选图预览，课堂就绪后再上传。
2. 选择本地图片，或点击粘贴区域后按 Ctrl+V / ⌘V。
3. 检查“待上传图片”，点击“确认上传”。成功后显示“当前教学图片”。
4. 换图后停顿一下，再讲对应内容。学生按现有课堂策略回应，上传不会自动解题。
5. 新图替换当前图，之前的课堂知识保留；可以重新选择旧图，或移除当前图继续纯语音/文字讲课。

用户负责截取希望展示的内容。整张截图里的可见内容都可用于课堂理解，不增加自动答案遮挡。

## 输入和模型

- PNG、JPEG、静态 WebP；单张不超过 5 MiB，单边不超过8192像素、总像素不超过1600万。
- 每次课堂图片文件总量不超过64 MiB；重复图片按内容去重，不重复保存文件。
- 图片验证与上传不调用模型。需要看图时，把对应截图与文字放入原有学生模型请求。
- 文字请求沿用 `LLM_MODEL`；有图的学生请求使用 `LLM_IMAGE_MODEL`，默认 `deepseek-flash`。
- 仍是同一个学生角色、画像、知识状态及发言策略，没有独立看图AI。
- 同图在后续请求中仍可能产生图片Token用量，不把文件复用等同于免费。
- 看见不等于理解；题目之外未教过的领域知识不能自动补齐，模糊数字或图示不能猜。

接口格式依据：[DeepSeek图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)；图片校验使用Pillow。

## 数据与时序

- 原始截图保存在 `logs/<课堂编号>.images/`，使用内容SHA-256作为内部编号，不使用用户文件名构造路径。
- 讲解来源记录关联的图片编号；更换当前图不能改写已经排队或处理中的发言对应图片。
- 语音按VAD分段在16kHz采集流中的开始位置绑定图片，不使用转写完成时的当前图。
- 不合并不同图片的教学批次。旧图片仅作为历史材料保留，不把所有历史图片发进每次请求。
- 切换图片会取消旧候选发言；原问题继续按旧图更新课堂知识，避免旧回答在新图上抢答。
- 上传失败不切换当前图。若上传响应与状态核对都失败，暂停麦克风及文字讲授，显示“核对当前图”；该读取操作不调用模型。
- 课堂结束或连接断开后的迟到上传响应不能恢复旧图或进入新课堂。
- 调试台、WebSocket事件和JSONL导出只保留图片关联，不记录Base64图片二进制；原图文件随课堂保存在本机，不自动删除。

## API

| 路径 | 行为 |
| --- | --- |
| `POST /api/sessions/{sid}/image` | 原始图片字节上传，成功才切换当前图；有流式大小限制 |
| `GET /api/sessions/{sid}/image` | 只读核对当前图片，无模型调用 |
| `POST /api/sessions/{sid}/image/clear` | 移除当前图，保留历史文件与知识 |
| `GET /api/sessions/{sid}/images/{image_id}` | 读取本机预览，限定编号和路径，禁止跨站读取 |

复用本机请求防护；预览响应设置同源资源限制、禁止嗅探和缓存。

## 报告边界

本轮不新增报告图片分析。文本报告会获得“课堂展示过图片但本次报告未收到图片内容”的提示，避免仅因未口述而判漏讲或臆测图中知识错误。仍保留原报告结构与长度。

当前体验版已知问题：2026-10-14的比热容试讲中，学生实际读出公式、图片数据并正确计算，但报告仍可能声称没有AI回应、把AI计算归为教师示范，或建议重复已经布置的动作。这是报告评价与角色归属问题；按用户要求本轮保留，不能用报告结论代替截图识别验收。
