# 历史讲授按实际发送批次整合：实现与回归

## 变化

在 `codex/classroom-history` 分支，历史教师消息从逐条 ASR 转写调整为一次学生模型请求对应一条讲授消息。正文逐段采用该请求中 `new_teacher_segments` 的原文，以换行保留片段边界，不润色、纠错或补写。

从普通文本或带图片请求的文本部分读取数据，只处理 `student` 阶段的新讲授；系统提示词、旧上下文、恢复发言及知识复核请求不作为新讲授。老师批次位于首次请求事件的位置，学生实际回复保留发言顺序，不强行配对。

相同来源、顺序和文本的重试合并。只有匹配的 `state.processed_sources` 才标记已处理；模型原始输出或请求日志不等于成功处理。失败或未找到成功记录时显示提示。没有可确认批次的转写保留原位置，标注“发送批次未确认”。

每个批次可展开原始转写，逐段显示原文与时间；原始转写未记录时明确提示，不拿提交文本冒充原始转写。展开前不创建全部原文节点，减轻长课堂初次渲染负担。不增加图片展示或续讲功能。

## 接口和缓存

保留原有历史接口与每批最多 50 条展示消息的分页方式。教师批次增加：

- `source_ids`：批次来源及顺序，仅作内部核对，页面不显示内部编号。
- `segments`：各段实际提交文本、对应原始转写及原始时间。
- `request_count`：完全相同批次的请求次数。
- `processing_status`：`submitted`、`processed`、`failed` 或未确认片段的 `unconfirmed`。
- `had_failure`：保留此前失败、后续重试成功的事实。

时间字段为首次请求时间。未确认片段仍使用原转写时间。批次作为整体分页，不跨页拆分。正文不读取完整提示词或状态，原始模型请求也不返回页面。

缓存格式从版本 1 升为版本 2，旧课堂自动重新整理。原始日志和独立报告缓存保持不变，不调整实时课堂、模型提示词或发送机制。

## 自动验证

- 历史单元测试：**26 项通过**。覆盖批次顺序、多队列片段、实际请求文本快照、后续审核不覆盖已提交文本、普通与带图片文本结构、自动修复和手动重试合并、失败状态、未确认片段、其他阶段过滤、损坏批次、分页和缓存升级。
- 全量离线套件：**474 passed，8 skipped**。当前主目录具备部分本机模型与语音样本，跳过项数量与前一次 worktree 验收不同；跳过未计为通过。
- 浏览器回归：受控课堂由 129 条转写整合为 127 条教师消息，加 3 条学生发言，共 130 条展示消息。验证批次正文、逐段原文展开、失败与未确认提示、分页、画像、报告读取和失败手动重试、缓存复用及原始日志下载。
- 导航、刷新、前进后退、桌面及 390 px 窄屏正常；测试音源下切换历史仍持续发送麦克风帧，课堂 WebSocket 不关闭。
- 浏览器真实旧日志回放：通过真实历史 API 加载截图对应课堂，核对 54 段批次的正文和展开后的 54 条原始转写，无页面错误和非预期 HTTP 错误。报告接口在该回放场景中明确拦截为未生成，不重跑旧课堂报告；报告功能另由受控课堂场景验证。

## 真实旧日志核对与性能

测试只读原文件，并在独立临时目录副本中生成派生缓存；前后校验原文件 SHA-256 一致。

| 截图对应课堂 `95881d605634` | 42,155,842 B | 456 | 16 | 3 | 19 | 290.24 ms | 1.11 ms |
| 另一堂旧课 `6a06f0778766` | 32,219,675 B | 166 | 8 | 2 | 10 | 214.59 ms | 0.92 ms |

所有批次的来源顺序、实际提交文本和首次请求时间均与原请求记录逐项一致；学生回复一致，所有原转写均有对应批次，没有遗失或额外未确认片段。截图对应的目标批次包含 **54 个片段、590 个正文字符**，换行分隔符不计入该字符数。

缓存重启复用场景通过禁止打开原 JSONL 核验，原日志重读为 0。另以合成的约 30 MB、60 MB 重复上下文日志回归：首次整理约 48.75 ms、83.90 ms，缓存后读取约 1.00 ms、0.79 ms；后台整理期间事件循环最大采样间隔约 7.08 ms。以上为本机测量，不是其他设备耗时承诺。

**本轮付费 API 调用为 0。** 使用已有真实日志及受控报告替身，没有重新讲课或重新生成真实报告。旧日志、截图及完整回放结果保存在忽略的测试目录或临时目录，不提交课堂数据。
