## 实际改动

### 总结报告与评分

- 后端逐段选择有效审核文本。审核关闭、失败或没有有效审核文本时，采用原始转写。兼容旧记录中的 `reviewed`、`corrected` 和 `unchanged` 成功状态。
- 发给总结 AI 的课堂记录保留采用的文字、角色、来源和输入类型，移除审核状态、原文及审核前后对照。
- 短课、长课分段、合并与最终报告统一分析已有课堂内容。核对全课及后续澄清后，可以指出具体解释、推理或回应缺口，不假定教师在记录之外补讲过。
- 移除针对未经审核语音的报告拒绝和评分证据过滤。逐字引用、角色、来源、教学动作归属和问答时序校验继续生效。
- `asr_empty` 继续保存在原始日志中，本身不再导致整课采集不完整或清空全部评分。实际音频错误继续沿用既有处理。
- 没有讲授或只有问候、试音时，五维评分留空。有明确低档教学行为时，仍可按证据得到 1.0 分。
- 含教师语音的报告页与 Markdown 导出各显示一次转写误差提示。纯文字课堂省略这条提示。
- 内容准确可以正常提出文字诊断。现有评分器尚未实现内容准确的数值判定，该维度仍显示资料待核对。

### 学生字段兼容与认知复核

- 仅在 `student` 和 `student_resume` 的结构校验前忽略 `question_updates[*].attempts`、`response_request_updates[*].input_revision`。其他未知字段继续校验报错。
- 原始 `llm_output.raw` 保持完整。`student_recovery` 事件用 `readonly_fields_ignored` 记录处理阶段、尝试次数、字段路径、模型原值及原因。
- 正式课堂详情和 `/debug` 可查看兼容事件。兼容处理本身不触发错误状态或重试，实际提问次数由程序在发布学生回应时增加。
- 知识版本错误显示条目 ID、预期与实际版本，以及该条目原有和本轮声明的依赖状态。修正提示要求同时核查依赖，避免只修版本后再因同一冲突前提失败。
- 学生与知识复核提示明确要求，重申结论不足以移除既有推导依赖。缺口仍在时保留依赖和疑问。有新的有效解释、例子、条件或证据时，可以解除相应依赖。

### 定向真实 API 验收

目的地为 `https://api.deepseek.com/chat/completions`，模型为 `deepseek-chat`。真实调用前，自动审批要求进一步明确课堂数据的外发目的地。用户明确确认后执行。

整批上限为 12 次，实际累计 **9 次请求、9 次响应**。其中包含首轮发现问题的请求，所有记录均保留。输入 67,252 tokens，其中缓存命中 45,184、未命中 22,068。输出 4,499 tokens，总计 71,751 tokens。用量取供应商响应中的 usage 字段。

首轮 7 次请求中，报告、`t11` 和重复断言复核通过。`t9` 仍出现版本修正后依赖校验失败，因此进一步补充具体依赖状态。

首轮独立解释对照夹具曾因列表位置变化撤回错误条目，使有效的模型输出被错误退回。这是验收脚本的问题。现已按知识 ID 定位撤回条目，并增加离线自检。首轮模型的正确输出也通过了修正后的夹具校验。

随后仅复测 `t9` 和独立解释两项，各用 1 次请求通过，累计 9 次。复测执行器继承上一轮请求和用量，保留上一轮结果。前后两轮各自运行期间的后端源码哈希稳定。
