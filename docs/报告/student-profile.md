# 学生画像接入说明

本模块在现有开发调试界面中实现课前生成、编辑与确认画像，再沿用现有课堂认知、发言和课后报告链路。生成画像不需要安装 ASR；创建语音试讲仍需要已选择的本机模型。

## 使用与覆盖规则

1. 教学主题必填；年级、学科默认由 AI 判断，均支持“其他”自定义。
2. 学生水平为基础薄弱、普通水平、基础扎实，默认普通水平；课型为新课、复习课、综合应用课，默认新课；教材版本默认空，在更多设置中填写。
3. 准备讲的知识点独立保留。填写后作为生成约束，空白时由 AI 补全。
4. 学生画像包含已有知识、理解基础、知识边界和可能的理解困难。AI 可生成合理的前置知识，教师检查后确认。直接手写画像也可使用。
5. 画像已有非空内容时，生成按钮显示覆盖确认弹窗；取消、Escape、网络失败、超时或无效响应均保留现有内容。成功后只替换画像并补空年级、学科、知识点。
6. 生成期间锁定教学表单及创建按钮。点击“创建试讲”即确认当前设定；课堂内不能修改画像。创建时画像去除空白后必须非空，统一提示“请生成或填写学生设定，再创建试讲嗷~”。

## 接口与兼容

`POST /api/student-profile` 使用与其余本机 POST 相同的来源检查。请求只有以下教学设置，拒绝课堂历史、动态状态、审核词表等额外字段。

| 字段 | 规则 |
| --- | --- |
| `topic` | 必填，去除首尾空白，最多 500 字符 |
| `points` | 默认空，最多 3000 字符；用户已填时原文保留 |
| `grade`、`subject` | 默认空表示 AI 判断，支持自定义，分别最多 100 字符 |
| `student_level` | `weak` / `normal` / `strong`，默认 `normal` |
| `lesson_type` | `new` / `review` / `application`，默认 `new` |
| `textbook` | 默认空，最多 200 字符；未填时不虚构具体教材版本 |

成功响应包含非空的 `grade`、`subject`、`points`、`student_profile`，画像最多 3000 字符。服务端强制保留请求中已有的年级、学科和知识点。前端在完整响应校验成功后才回填。请求参数错误返回 422，模型、超时或生成结果错误返回 502 与 `detail`；总生成时限 90 秒，结构不合格最多修复一次。

WebSocket `/ws/session` 的 `start.lesson` 接收相同教学设置和必需的 `student_profile`。校验先于 ASR 申请和课堂创建；`Session.start()` 再校验并复制设置，避免绕过接口或外部修改。`ready`、`finished` 事件均包含确认后的 `lesson`。

旧请求显式传入的非空 `prerequisites`、`level` 分别按“已有知识”“理解基础”合并成画像，保留原文；新日志只写新字段。没有显式基础的旧请求不会自动补默认画像。请求只要显式带有 `student_profile`，就以该值为准，空值不能靠旧字段绕过检查。仓库内的测试与回放入口已更新。历史课堂日志不改写，仍可读取并生成报告。

## 课堂与报告

- 画像生成只使用教学设置，独立于课堂和 ASR，不创建课堂日志。
- 创建课堂时，既有 `preparation` 调用同时整理教学范围和提取 `initial_prerequisites`，不额外增加解析调用。前置条目必须逐字出现在确认画像中，禁止改写或补充；不合格结果参与既有结构修复。
- 前置条目作为 `p1…` 来源进入课堂。初始 `StudentState` 仍为版本 0，知识、问题和事件为空。画像中的困难与未知内容依靠提取提示词做语义排除，原文匹配校验本身不能证明一句话确实表达“已知”。
- 学生 System 包含核心规则、确认画像及明确标记为待学范围的主题和知识点。画像只能影响学生基础与理解特点，不能覆盖身份、知识来源和发言规则。
- 最近 16 个成功处理的教师批次 / 实际学生回复按顺序作为 User / Assistant 历史；失败重试不重复写历史，候选回复被抑制时不写 Assistant。学生回复不能成为知识来源。认知和相关教师来源继续使用原有受控上下文。
- 日志保留完整画像。报告分析只传入主题、知识点、年级、学科、水平、课型与教材版本，以及实际课堂内容；画像和旧基础文本不占用报告分析窗口，也不作为教师讲授证据。

## 验证

离线回归：

```sh
./.venv/bin/python -m pytest -q
```

浏览器交互与布局验证使用模拟 API，不调用云端、不要求 ASR，不需要预先启动服务。需要 Node.js、Playwright 和浏览器；可通过 `NODE_PATH` 指向已有 Playwright，`CHROME_PATH` 指定 Chrome 可执行文件：

```sh
node tests/student_profile_browser.cjs
```

默认截图为系统临时目录下的 `student-profile-desktop.png`、`student-profile-mobile.png`；可设置 `PROFILE_SCREENSHOT_DIR`。测试覆盖主题生成、回填、自定义选项、覆盖取消、服务失败、无效响应、重复提交、手写创建、空白校验和窄屏布局。

真实模型抽样使用已配置的模型及密钥，只发送脚本中的合成数据；最多 24 次请求，无需服务或 ASR，会使用 API 额度：

```sh
./.venv/bin/python tests/live_student_profile.py --live
```

依次检查主题推断、薄弱 / 扎实两种水平、前置原文摘录、生成画像下的未讲公式、未讲新造规则、未完整纠正与完整纠正。结果和合成课堂日志保存在 `logs/student-profile-live-*/`，其中 `summary.json` 包含生成全文和行为验证结果，便于人工复核。真实模型的少量抽样不代表所有学科、措辞和知识边界都能稳定通过。

2026-10-12 验证结果：离线回归 196 项通过、3 项跳过；Chrome 桌面及 390px 窄屏交互测试通过，覆盖取消、无效结果、断网、超时及重复点击；模型文件检查通过。最终真实模型抽样共 13 次请求：主题“欧姆定律”推断为九年级物理；生成画像下学生在课前拒绝给出未讲公式；星星运算先按临时规则回答 6，教师撤回后表示完整规则未知，完整纠正后回答 5，并保留知识修订。人工复核了三档水平画像及提取的前置条目。
