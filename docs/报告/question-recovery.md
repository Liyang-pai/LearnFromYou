# 追问漏登记的定向修复与课堂恢复

模型有时会输出 `candidate.kind="question"`、`question_id="q2"`，却既没有在本轮 `question_updates` 登记 `q2`，也没有对应的已有疑问。旧逻辑在发言校验时抛出“候选问题不在问题库中”，导致本轮学习记录全部拒绝提交并暂停队列。这里的疑问列表属于学生课堂提问生命周期，与给学生出题的题库无关。

## 恢复规则

1. `ModelClient.generate()` 解析 JSON 后，调用可选的同步结果校验回调。课堂调用使用状态副本做完整预校验，修复期间不提交知识、疑问、事件、处理编号或历史。
2. 追问引用不存在的疑问时，抛出专用 `MissingQuestionError`，携带问题编号，并反馈“请在 question_updates 中补齐对应疑问记录，或将 candidate 改为 silence”。
3. 首次失败会把具体错误、模型刚才的输出一起送入一次修复请求。JSON 格式修复与课堂关联修复共用原有两次请求上限，不在课堂外层再增加自动重试。
4. 最后一次输出若仍仅漏登记追问，将候选替换为 `silence`，完整重新校验其他记录，通过后正常提交。不会自动补建疑问、发送这次追问或增加提问次数；后续课堂内容继续按序处理。
5. 最终 JSON 无法解析、网络失败、无效知识或候选来源、错误的纠正关联、缺少问题关闭依据等错误仍使整轮失败。原状态保持不变，批次保留，等待手动重试。

缺少或为空的问题编号同样按“追问关联不存在”处理，前提是候选正文与来源及其他记录通过校验。已解决疑问继续抑制；已暂缓或达到上限的疑问按文末的教师邀请例外规则处理。修复期间收到新教师输入，旧候选回复仍会失效；静音时仍更新认知。

## 接口与日志

对外教学设置、模型输出字段、课堂状态和已有消息保持兼容。内部增加 `result_validator(result, final_attempt)` 回调：返回有效的 `StudentResult`，或抛出校验异常；其结果仍需经过课堂提交时的完整校验。

新增调试事件：

- `student_validation_error`：包含尝试编号和具体错误，用于显示自动修复过程，不切换到手动重试状态。
- `student_recovery`：包含跳过原因、原问题编号、来源、尝试编号及“异常追问已跳过，课堂继续”。原始模型输出仍保存在 `llm_output`，不会被静默改写。

成功恢复后只提交一次状态、只记一次教师批次历史，不发送异常回复，也不设置失败批次。真正失败的结果仍触发现有 `error` 和手动重试按钮。

浏览器测试启动真实本机服务，但使用模拟 ASR 和 `MockTransport` 完全替换云端模型；前端副本和课堂日志均位于系统临时目录，不要求预先启动服务或安装 ASR：

```sh
node tests/question_recovery_browser.cjs
```

需要 Node.js、Playwright 和 Chrome；可用 `NODE_PATH` 指定包目录，`CHROME_PATH` 指定浏览器路径，`LFY_TEST_PYTHON` 指定 Python。测试确认页面连续漏登记后无需手动重试、不发出异常追问，且下一段讲授正常更新认知。结束时输出临时截图路径。

本修复集中处理追问关联异常，不调整画像和对话历史输入，也不处理教学设置残留。修复是否生效可通过离线测试确定，无需重新发送用户实际课堂数据。

## 2026-10-14：冲突说明被误拦截的回复修复

模型可能生成“老师，我在听，但这两种说法对不上”的回复，同时将冲突双方填进 `candidate.knowledge_ids`。此前程序发现其中任一知识处于 `unclear` / `conflict` / `invalid` 或待复核时，直接把整条回复替换成沉默，没有给模型纠正关联的机会。

现在，`knowledge_ids` 明确只表示真正用于推导答案的前提；复述旧说法、描述障碍、对比冲突双方仅在 `sources` 保留来源，不填入这些知识 ID。提示词和字段说明均给出该区分。

候选仍声明采用不可用前提时，抛出 `RestrictedKnowledgeError`，将具体 ID 和修正要求送入现有的一次修复请求。修复可以保留说明困惑的正文并纠正关联，或将确定答案改写为说明障碍。程序不会自行删掉前提来放行原答案，也不会根据“老师”“不懂”等词放行。

若第二次仍失败，完整校验其他记录后只跳过候选发言，保留有效学习进度，发送 `student_recovery`（`code=restricted_knowledge_reference`）。页面显示“回复仍使用不可用的知识前提，已跳过；课堂继续”，避免模型备注“直接回应”掩盖实际跳过结果。追问漏登记先独立校验，不再被不可用前提的静默清空遮蔽。两类关联错误与 JSON 修复共用两次请求预算。

发言等待期间若所用前提后来变成不可用，仍取消回复，并记录具体的发言控制原因。静音、新输入使旧回复失效、教师停顿及提问次数限制沿用原规则。

离线专项测试：`./.venv/bin/python -m pytest -q tests/test_reply_recovery.py tests/test_question_recovery.py tests/test_knowledge_machine.py tests/test_session.py tests/test_policy.py`。覆盖正常困惑说明的实际投递、冲突前提误填、追问同时漏登记、两次失败后的课堂连续性，以及不可用前提仍不得推导确定答案。

### 历史补丁：已暂缓疑问不应使教师点名后的回应消失（已被下述方案替代）

日志 `3df79a40c23c.jsonl` 的学生先两次发出同一问题，问题被标记为 `deferred`；随后还能通过 `ack` 回应教师。最后教师问“还有问题吗”，模型再次输出同一问题的 `question`，被次数上限直接替换为沉默。这与知识前提误填是两个不同原因。

当时的补丁区分主动追问和回应教师：前者仍最多两次，后者可以用 `answer/ack` 说明当前理解或未理解的地方，不再请求重复解释。教师明确要求回应却生成已暂缓问题的第三次追问时，抛出 `DeferredQuestionReplyError`，在现有一次修复机会中要求改写；不解封原问题、不增加次数、不用新 ID 绕过限制。

如果修复输出仍是已暂缓问题的重复追问，完整验证其他记录后，将该候选替换为固定的简短确认：“我在听，刚才的问题还没想明白，我先继续听您讲。”该确认不包含领域结论、不采用任何知识前提，只引用本轮教师来源，并记录 `student_recovery(code=deferred_question_reply)`。只在教师明确询问且旧问题未解决时使用此恢复；已解决问题、未被点名的主动重复、无效知识记录或无效来源仍沿用原有限制。发言仍受静音、停顿和新输入使旧回复失效的控制。

新增测试覆盖两次追问后的点名回应、模型正常改写及两次重复后的确认、暂缓问题与新问题的独立生命周期，以及无效更新不得被恢复逻辑掩盖。

2026-10-12 验证结果：新增恢复专项测试 13 项通过，完整回归 209 项通过、3 项跳过；真实 Chrome 与离线课堂服务的联调通过，模型文件检查通过。更新后需重启后端并刷新页面，以加载新的课堂校验与恢复逻辑。


## 2026-10-14：教师邀请下的单次提问例外（当前实现）

旧的 `DeferredQuestionReplyError` 和固定 `ack` 回退已移除。模型必须主动根据实际已发次数遵守通常两次上限，不能提前把候选计入次数或将第二次候选标成已暂缓。程序归并同义疑问，实际发出后才改变次数与暂缓状态。

教师请求增加 `kind`：`invite_questions`、`answer`、`check_understanding`、`check_audio`。旧数据默认 `answer`，不授予例外。邀请须提供 `invitation_source_id` 和逐字 `invitation_quote`；语义由原学生模型同次判断，不增加审核模型调用。否定、假设、引用示例及普通点名不应分类为邀请。

已暂缓疑问保持 `question`，候选附 `question_release_request={question_id,response_request_id,reason}`，并在 `response_request_ids` 只关联该邀请、在 `sources` 保留邀请来源。程序验证原疑问、邀请原文、当前输入修订号、关联及未使用状态。同一教师来源只登记一次邀请，不能换请求 ID 或问题领取第二次许可。校验不消耗许可；实际 `reply` 后计数加一、邀请变为已回应，原疑问仍暂缓。

一般回应不因“被点名”自动解封疑问。“懂吗 / 在吗”及检查声音按真实意图回应，不能用 `answer/ack` 隐藏重复请求解释。模型语义分类和自由文本是否完全一致仍有模型可靠性边界；程序不声称仅凭引用就能证明语义。

新输入或教师讲话开始使旧邀请和候选失效，普通待回答请求保留。静音期间登记邀请而不发言；没有新输入时，解除静音重新生成提问与申请。恢复路径允许按邀请使用 `question`，不再要求合并所有请求成 `answer/ack`。发出前再次检查疑问与知识状态，停顿和静音规则继续生效。

申请失败进入原有一次修复；最终失败只跳过候选及无效邀请登记，完整验证其他更新后提交有效学习记录。无效知识更新仍使整轮失败。`student_recovery` 记录 `question_release_denied`；`question_release` 分别记录 `requested/rejected/approved/waiting/delivered/cancelled/denied`，`invitation_expired` 记录邀请过期。候选、获准和实际发出在页面分开显示。

运行身份在进程启动时固定，含代码目录、进程、启动时间、可取得的提交号、能力标识和覆盖提示词/结构/控制代码的规则指纹。`ready` 另记课堂实际学生提示词指纹，每次模型请求另记完整系统提示词及 schema 的指纹。历史日志不改写，新增字段兼容默认值，认知结构版本保持 2。
