# 学生画像 Prompt 实测报告

日期：2026-10-15（北京时间）
模型：DeepSeek `deepseek-chat`，项目配置的 `https://api.deepseek.com`。

## 结论

新画像生成 Prompt 在本次矩阵课抽样中改善了等差数列前置遗漏，但尚未全部通过。跨学科基础仍可能错放栏目；非已有知识栏目仍夹带本课答案；未入库基础在课堂中被使用后，可能通过学生自己的发言补成知识并错标教师来源。这些是实际观察到的结果，不能由离线测试通过推断已经解决。

本轮只测试和记录结果，没有继续修改产品 Prompt 或认知逻辑。

## 范围与调用

- 7 次画像生成任务：修改前的矩阵课普通水平 1 次；修改后的矩阵课普通水平 2 次、薄弱水平 1 次、扎实水平 1 次；九年级欧姆定律 1 次；八年级一次函数图像与性质 1 次。
- 每份画像均调用现有 preparation 提取器，以真实原文匹配校验取得初始知识。
- 11 轮合成教师输入，调用现有学生 Prompt、结果校验、知识状态提交和实际发言登记函数。使用生成画像，不手动补知识。
- 总计 29 次 API 请求，包含 4 次自动修复请求（画像结构 1 次、学生关联校验 3 次）；API 返回统计累计 161689 tokens（输入 148072，输出 13617）。未估算费用。
- 课堂使用文字输入及生产认知校验函数；未覆盖麦克风、ASR、TTS、浏览器操作、课堂调度和长课时稳定性。
- 除普通水平矩阵画像重复生成 2 次外，其余场景各 1 次；这是针对性抽样，不是统计意义上的稳定率。

## 观察结果

| 检查项 | 实际结果 | 判断 |
| --- | --- | --- |
| 修改前矩阵画像对照 | 仅提取 3 条基础，没有等差数列求和；部分二维地址知识放在理解基础而未提取 | 重现遗漏风险 |
| 修改后矩阵画像覆盖 | 普通 2 份、薄弱 1 份、扎实 1 份均写出等差数列求和；分别提取 9、7、9、8 条基础 | 本次抽样改善 |
| 已知公式回答 | 普通学生答出 `1+…+10=55`，列出求和公式，knowledge_ids 引用 p6 | 通过 |
| 未讲矩阵映射 | 要求直接给出下三角矩阵压缩下标公式，普通学生说明未学过，没有输出公式 | 通过 |
| 已入库基础的矛盾 | 教师给出“不除以2”的新说法，学生登记 p6 与新知识的 open 冲突，未直接覆盖原基础 | 通过；首次候选关联错误后自动修复 |
| 教师明确纠正 | 明确撤回不除以2的说法后，冲突 resolved，引用 t4，恢复使用 p6 回答 | 通过；首次修订号错误后自动修复 |
| 欧姆定律新课边界 | 尚未讲授时，学生拒绝输出公式和计算 6V/3Ω 的电流 | 本轮通过 |
| 薄弱画像夹带的矩阵长度 | 画像在理解困难里出现 `n(n+1)/2` 和具体存储方案，但直接问存储元素个数时学生仍表示不会 | 画像边界不合格；本轮未导致该答案泄漏 |
| 扎实画像的复杂度描述 | 理解基础出现“空间复杂度从 O(n²) 降到 O(n(n+1)/2)”；两者同为 O(n²)，此表述不准确。课堂回答能说明没有降低数量级 | 画像准确性不合格；课堂回答正确 |
| 一次函数待学结论 | 知识边界直接出现一般式，理解困难直接出现“k 的符号决定增减性，b 不影响增减性” | 画像边界不合格 |
| 一次函数课堂追问 | 学生只复述已知正比例函数性质，表示不知道一般一次函数 b 的影响 | 本轮未观察到对应答案泄漏 |
| 跨学科基础入库 | 欧姆画像把乘除、等式变形、正反比例放在理解基础；提取的 10 条前置均未包含这些数学基础 | 不通过 |
| 未入库基础回答 | 问正反比例定义时答对，但 knowledge_ids=[]，sources 仅为教师提问 t1，无对应知识条目 | 知识追溯不完整 |
| 未入库基础发生冲突 | 后续教师把正比例说成乘积一定时，学生能口头质疑并建立冲突，但新建 k_math_direct，把自己的上一轮定义归到 t1 提问来源 | 不通过：知识来源错误 |

## 关键证据：未入库基础的来源错误

初始欧姆画像的理解基础写道：

> 学生能进行简单的数学运算，包括乘除运算和等式的变形，能理解正比例、反比例关系的数学含义。

这句没有进入 initial_prerequisites，也没有进入初始 understood。

第一轮教师 t1：

> 先不谈电学，请回答你以前学过的数学知识：正比例和反比例关系分别是什么意思？

学生正确回答定义，knowledge_updates=[]，candidate.knowledge_ids=[]，candidate.sources=["t1"]。

第二轮教师 t2：

> 下面仍是普通数学里的正比例关系，没有换定义。我给出一个说法：两个量成正比例时，它们的乘积一定，而不是比值一定。请判断是否与你原来学过的知识一致。

模型新建：

```json
{
  "id": "k_math_direct",
  "text": "两个量成正比例时，它们的比值一定，一种量随另一种量成倍变化。",
  "status": "understood",
  "sources": ["t1"],
  "reason": "学生已学数学知识，上一轮已作答。"
}
```

随后将它与 t2 的错误说法关联成冲突。t1 实际上只提问，没有讲过定义；学生自己的上一轮发言被变相作为知识依据。生产校验仅验证来源 ID 存在，未拦住这次语义来源错配。此结果表明“能说出矛盾”不等于冲突的知识依据已正确入库。

## 离线回归

全量回归首次运行：334 passed、8 skipped、2 failed。两项失败都发生在启动测试绑定本机端口时，原因是沙箱权限。允许本机端口后重跑启动测试：4 passed、1 skipped；其中包含上述两项失败及两项先前已通过用例。合计 336 个唯一测试通过、8 个跳过。另有现有 Starlette/httpx 弃用警告。

新增实测脚本通过语法检查，修改通过 git diff --check。离线回归不验证真实模型的语义表现。

## 下一步建议

优先继续收紧画像生成器：明确按四个栏目审查，数学等具体基础只能进入已有知识；未知和困难栏目仅描述缺口，不写目标公式、定理或具体存储方案；检查基础扎实与薄弱的差异及数学表述准确性。保持同一组实测场景复验。

若要防住本次观察到的来源错误，仅依赖画像生成 Prompt 的成功率不构成强保证；需要另行决定是否加强课堂端对未登记基础和来源语义的约束。本报告未实施这些额外改动。
