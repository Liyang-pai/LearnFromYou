## 1. 优先去掉重复的教师原文

当前 `conversation` 保存成功处理的教师批次；下一轮又通过 `teacher_sources` 提供相关原文。最后一轮的 119 段 `teacher_sources` 中，有 **118 段**已经出现在历史教师消息中，且整条来源对象完全相同。另一段是当前新问题。

此外，`new_teacher_segments` 中的当前问题也出现在 `teacher_sources` 中。明确前置知识则同时存在于 `explicit_prerequisites` 与 `current_state.knowledge`，原始画像还描述过它们。

建议建立一份唯一的教师来源表，按 ID 引用；让历史对话保留实际学生发言与必要的问答关系，教师原文统一从来源表提供。本轮新片段可以保留完整对象，历史来源表排除同 ID，避免再次复制。初始前置知识也选择一个权威位置。

风险与验证：不能直接删除所有历史讲授。本次历史里有 165 段，而 `teacher_sources` 只有 119 段；直接删历史会同时丢掉未被选入的 47 段。应先明确这些内容是否仍有用途，保留所需部分，并验证问答承接、复述、纠错与来源校验。去重应以来源 ID 与内容一致为依据，不能把不同来源里相近的话误合并。

## 2. 让知识状态与来源按任务选择

系统已经做了来源筛选，但筛选集合包含所有知识引用、历史版本、问题与纠正等引用；知识越多，选中的原文仍会增长。同时，`learning_context()` 会发送当前全部知识以及其他状态字段。

建议分两层组织：保留简短的全课知识索引与全局安全状态，按当前输入、未解决疑问和待复核事项选择详细知识；再补全所选知识的依赖、冲突双方、最新修订、纠正与必要原文。不要仅按最近 N 条截断。

“复述刚刚内容”与“还有什么问题”有全课范围需求，应使用覆盖全课的简明索引或摘要，不能只给最后一个概念。摘要只能归纳课堂已讲内容，不能补入模型常识；它也不能替代纠正、失效、依赖和来源的权威记录。若需要额外模型调用生成摘要，应把摘要费用一起纳入比较。

本次末轮没有知识历史、冲突、待复核或疑问条目，因此这些空字段不是本次膨胀的主要来源，优先处理知识正文与教师原文。

## 3. 精简输出 Schema 和序列化

系统消息中约一半字符来自 JSON Schema（7,977 / 15,532）。可先去掉不影响验证的 `title`，合并与系统正文重复的字段说明，保留关键类型、枚举、必填项、长度上限与关联规则。输入 JSON 也可以取消冒号和逗号后的空格。

后端继续使用完整模型校验，不因提示词变短放松检查。Schema 的 `description` 中包含行为提示，不能一概删除；应逐项区分重复说明与必要规则。

本次曾因 `candidate.sources` 输出 14 项、超过 12 项上限而重试。精简时应保留或更明确强调此类上限，避免节省输入却增加重试。该次重试实际新增 25,898 token，但其中 25,216 输入 token 命中缓存，因此不能按 token 总量推算同等比例费用。

## 4. 合并重复行为规则，明确判断顺序

当前系统正文对以下内容有多处交叉说明：知识边界与来源、冲突或失效知识的使用、问题次数与暂缓、教师邀请与例外申请、候选回复和关联字段。

可以整理为固定判断顺序：识别本轮教师意图 → 更新知识及旧疑问 → 检查是否必须回应 → 判断关键理解障碍 → 检查提问次数及邀请 → 输出状态增量与一个候选。把同一规则的例外放在同一处，减少模型在远距离段落间整合条件的负担。

必须保留的语义包括：不借用未学常识、暂定性质沿依赖传递、纠正使旧知识失效、说明冲突不等于采用冲突前提、同一问题沿用 ID、两次提问后的暂缓与邀请例外。不要为缩短文本删掉此前修复过的边界条件。

## 5. 评估按职责拆分输出

当前一次学生调用同时承担知识更新、问题生命周期、回应任务与自然回复生成，造成较大的输入和 Schema。可以评估将“认知更新”和“发言”分成不同结构，普通学习轮只使用必要结构；更进一步拆成两个模型调用则需要单独测量。

这属于第二阶段方案。拆分可能增加调用、重复输入与等待时间，也可能让发言读取到过期状态；只有在去重和精简之后仍有必要时再做。不能假设拆开一定省钱。

## 6. 缓存与验证方式

固定规则与固定 Schema 放在稳定前缀，避免每轮重排、插入变化字段；动态状态放在后部。本次代码已将系统消息置于首位，末轮有约 52.9% 输入命中缓存。仍应关注去重后“未命中输入 + 输出”的实际费用，而非只追求总 token 或缓存命中比例。

建议实施顺序：

1. 去重教师原文与前置知识，精简 JSON 空格和无用 Schema 元数据。
2. 合并系统正文中的重复规则，保留关键上限与例外。
3. 增加任务相关的知识、来源选择以及全课覆盖机制。
4. 最后评估职责拆分或额外摘要调用。

每步先做离线结构验证，再用有代表性的固定课堂比较实际模型行为：未知知识、纠错失效、依赖传播、追问暂缓与邀请、静音恢复、全课复述。记录输入、缓存命中与未命中、输出、重试、耗时和行为变化。真实模型回放会产生新的 API 费用，本文未执行。

原始日志没有计费单价和账单归属，因此不能精确把 0.4 元分配到各组成，也不能承诺去重后的具体节省比例。
