**修复后，学生发言正文仍只发送一次，13 轮整课回放全部首发通过。** 首次合并版因发言字段位置错误用了 24 次请求，修复后只用了 13 次。首次合并版和当时的回归记录保存在提交 `4142683`。

## 一、优化前的样子

原版在两处发送小纸的实际发言。`messages` 中的 `assistant` 消息把发言放在师生对话的原位置。本轮 `user` 输入中的 `previous_student_utterances_not_knowledge_sources` 还会再传一次正文，同时带上发言类型和引用的教师片段。

以下用 t7 的回答示意。正文取修复版实际发言的首句，省略其余消息和字段。

历史消息

~~~json
{"role":"assistant","content":"从记住的 N2 沿它的 tp 走，就到 N3，也就是 d 所在的外层位置。"}
~~~

assistant 是聊天模型 API 约定的消息角色名，表示「这条消息来自模型一方」。在 LearnFromYou 里，模型扮演的是学生小纸，所以 role: "assistant" 的意思就是「这句话是小纸说的」
本轮输入

~~~json
{
  "previous_student_utterances_not_knowledge_sources": [
    {
      "text": "从记住的 N2 沿它的 tp 走，就到 N3，也就是 d 所在的外层位置。",
      "kind": "answer",
      "sources": ["t7", "t5"]
    }
  ]
}
~~~

对话历史按最近 16 条师生消息取，独立列表按最近 8 条学生实际发言取。老师连续讲几轮后，某条学生发言可能已经滚出对话历史，但仍属于最近 8 条。合并需要保留两个窗口的覆盖范围。 [优化前 t8 请求](../../logs/2026-11-19_164721_5514a0d90671.jsonl#L93)

## 二、优化后出现的问题及原因

首次合并删掉独立列表，把发言正文、类型和来源一起序列化进 `assistant.content`。按同一句发言示意如下。

~~~json
{
  "role": "assistant",
  "content": "{\"text\":\"从记住的 N2 沿它的 tp 走，就到 N3，也就是 d 所在的外层位置。\",\"kind\":\"answer\",\"sources\":[\"t7\",\"t5\"]}"
}
~~~

历史 `assistant` 消息由此反复出现扁平的发言 JSON。本轮输出规范要求把 `text`、`kind` 和 `sources` 放在 `candidate` 里面。t8 的两次失败输出却把它们与 `knowledge_updates` 一起放在顶层。自动重试追加了第一次的错误 JSON，只提示有额外字段，第二次仍生成了同样的结构。整课有 **9 轮出现这类错误、11 次额外请求**，其中 t8 连续失败后经历了人工恢复。 [t8 首次输出](../../logs/2026-11-19-广义表纯文本回归-修改后/logs/2026-11-19_231519_a42f9b2fecd4.jsonl#L98) · [重试请求](../../logs/2026-11-19-广义表纯文本回归-修改后/logs/2026-11-19_231519_a42f9b2fecd4.jsonl#L100)

此前单独取 t8 和 t13 各做了一对对照。两条原样请求都复现了顶层字段错误，两条正文与元数据分离的请求都首发通过，并返回 `candidate.kind = "silence"`。这符合模型把历史发言的外形当作输出范例的解释。两轮对照和下文的整课复测分别计量。 [两轮对照记录](修改后_课堂回归记录.md#修复方案与小样本对照)

## 三、修复方案

1. 正常课堂和解除静音后都发送纯文本 `assistant.content`。先取最近 16 条师生消息，再把落在窗口外的近期学生发言补回。按实际发言记录去重，相同措辞的两次发言各自保留。
2. 在本轮输入里用 `history_reply_metadata` 传最近 8 条发言的编号、类型和教师来源。`reply_number` 按本次历史中 `assistant` 消息的出现顺序从 1 开始计数。
3. 校验识别到顶层发言字段时，重试提示直接列出要移入 `candidate` 的字段，允许知识和疑问更新继续放在顶层。重试输出仍须通过原有结构和课堂关联校验。
