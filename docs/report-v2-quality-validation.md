# 课堂报告 V2 · 教学分析与阅读质量验收

日期：2026-10-08。分支：`feature/trial-report-v2`，基线 `637b3cf`。只做本地修复、测试及受控真实验收，不推送、不更新 PR。

## 故障定位与修复

1. 历史课堂 `99035dfce2f8` 的教学分析阶段在 `ModelClient.generate → model_validate_json` 两次结构校验后失败，缓存保存 `diagnosis=null`，其余三阶段成功。这是生成失败，不是“没有教学问题”。历史代码的 `quiet_emit` 丢弃模型输出和具体字段错误，因此**无法追回当时究竟哪个字段违规**；本次不能宣称复现了同一份错误 JSON。
2. 原结构修复请求只说“不符合 schema”，没有错误字段及约束；现在记录本地原始响应、用量及去输入值的字段校验错误，并把具体约束反馈给唯一一次结构重试。截断、HTTP 错误和超时不自动重复收费请求。教师报告用明确失败提示和重试入口；空对象不能被记为新的教学分析成功。
3. 原诊断提示及程序只允许“学生实际疑问未解决”类不足，会删除纯教师讲授的教学改进意见。现区分学生疑问与教师讲法/检查机会；前者保留原有保守过滤，后者须引用实际已处理教师讲授，不能编造学生表现。补充后续解释引用，避免“教师暂缓演示”被写成“完全没有解释”。
4. 在同一个诊断请求生成简短总体评价，无新增摘要请求。页面和 Markdown 共用阅读层：总体评价、优点、优先两个问题及对应动作、学生理解；原文、复述、作答、统计和技术状态折叠。导出省去重复整段状态 JSON，完整记录仍在原缓存和网页详细依据中。
5. 统计区分实测零、未发生互动、未验证、未标注和记录缺失；会话时间与教师文本片段避免冒充录音时长、自然发言轮次。课中 AI 发言与课后模拟作答分开。
6. 保存后可用 `/?report=<课堂编号>` 直接重新读取，仅 GET；不自动生成或重试。证据按钮用发言者和时间命名，打开外层折叠区后准确高亮原文。

## 理解误判的真实复验

保留完全复制、换变量/数字、逐项任务完成、理由错误、部分回答和无课堂来源等旧防线。补充教师已演示任务与新题的对照，包括实际任务原文、作答原文、来源引用及核心步骤。

第一次新验证发现：模型在文字中承认只是颜色/场景改变，仍将三题标为“实质任务变化”。这证明只加提示和对照字段不够。加入程序守卫：**教师演示与新题核心步骤相同，即使模型给积极标签，也降为尚未验证**。缺少对照、任务原文或可核查推理则证据不足。步骤不同也不自动通过，仍须完成全部任务且理由、引用可靠。

## 真实教学反馈人工核对

使用现有《Python 列表与元组》课堂，全程复用教师记录、原复述和原作答；没有新课堂、伪造输入或改写 JSONL。

- 最终 3 条优点：生活化情境与易错点提醒；设问后澄清“不能改”与“不能读”；四点小结。课堂原文均支持这些教师行为，教学作用明确是可能的作用。
- 最终 2 个问题：采用文本的数字例子歧义（建议核对录音，不认定教师知识错误）；对象引用有语言解释但缺少运行/作答检查（承认后续解释，不认定教学失败）。
- 两条建议分别给出统一数字后让学生指认下标、用 `a`/`b` 同列表预测再运行的具体动作。新例子明确属于下次教学建议。
- 同一设问可是优点，例子数字可待核对；评价角度不同且各有原文支持，没有把正常认知冲突当失败。
- 本课没有实际学生发言，系统候选疑问不是学生已经提出的问题；真实学生理解证据不足。
- 生成结果保存后由新的 `ReportService` 实例读取，仍有总体评价、3 优点、2 不足及2建议；正常网页 API 同样读取成功。
