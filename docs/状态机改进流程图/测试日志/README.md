## 五种判断用普通话怎么理解

- 课堂推断理解：这次讲解足够，我能沿着已有基础理解；不等于老师说的事实已经被外部验证。
- 推断待确认：我暂时能接受，但中间有可补跳步，或我用到的前提还没确定。
- 理解障碍：缺少关键概念或依据，现在接不上；可以换一种讲法来理解。
- 矛盾待解决：同一条件下有两种互相冲突的说法，双方相关部分先停用，等老师说明。
- 已失效：老师明确撤回或纠正了这条旧说法，今后不再用，但仍保留它当时的记录。

## 这些记录到底测试了什么

教师输入是固定的文字案例，模型是真实配置的模型；不是录音转写实验。全部验收开启静音，所以日志里的“回答/追问”多为候选文字，不代表实际说出或播报。

当前八组通过记录都没有额外后台知识复核调用。尤其依赖案例在课堂当轮就完成了受影响结论的更新。后台自动复核的调度由离线自动测试覆盖，不应把这组真实日志宣传成后台调度的真实模型验收。

## 测试不严谨之处与改进

旧多路径案例只声明学生会加减法，却讲“乘2再加1”；模型理由进一步误称学生已有乘加基础。旧断言只核对表格变化已理解、图像仍不懂，没有核对这句基础归因。旧通过记录因此只能证明部分路径，不足以说明所有依据都严谨。

本次改进后，教师逐行用“输入数加自己，再加1”解释表格，再解释输入增加1为何输出增加2。加强断言：理解须有本轮来源，保留原图像条目的理解障碍，并禁止没有讲清楚的读图、斜率、截距被升级。第一次加强后的重测实际保留了图像障碍，但把“不学读图”这个安排存成了已理解知识；按“读图”关键词检查的断言误报了领域理解升级。随后修正断言，并加入课堂范围不得作为领域知识的检查；补充提示词后，最后一次只重测第二段讲解，复用前一次真实画像摘录和首轮认知，消耗1次请求并通过。新旧记录均保留；结果见下方最后一次多路径运行。

可补跳步案例的理由没有完整写出学生能补出的逆推过程，阅读版单独标注了这个局限。有限案例通过不能保证所有跳步或矛盾都判断准确。

## 想对照原始日志时

每行是一个事件。`transcript` 是教师输入；`llm_request` 是发给模型的请求（不是完成次数）；`llm_output` 是模型原始回答；`student_validation_error` 是程序拒绝的原因；`state` 是通过校验后提交的认知；`knowledge_review` 才代表额外后台知识复核。

`p` 开头表示画像基础，`t` 开头表示教师来源，其他知识ID用于连接各条结论。修订号表示同一知识变动到了哪一版；依赖中同时保存前提ID和所用版本。
