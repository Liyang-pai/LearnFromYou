# V1 认知状态管理改造说明

## 一、目的和边界

本次改动区分“学生当前的知识”“学生的问题”和“课堂发生的事件”，记录教师纠正知识的过程。原始星星运算回放曾把下课语保存为知识条目，因此为课堂事件提供独立位置。

本分支已基于 main 保留语音转文字审核、音频上传和 Windows 播报。独立“检验学生理解”模块已移除，普通课堂中的提问、回答和静音学习继续使用原来的课堂链路。没有新增模型调用，也没有修改已解决问题的处理规则。

## 二、状态结构

| 字段 | 用途 |
|---|---|
| `version` | 认知更新的版本号 |
| `knowledge` | 定义、概念、规则、因果关系、方法及纠正结论 |
| `open_questions` | 问题生命周期；保留 resolved 记录以防重复追问 |
| `recent_events` | 开场、任务、回答请求、结束和组织语言，最多最近 20 条 |
| `knowledge_history` | 修订前的知识、修订版本和替代条目的 ID |

旧 `questions` 输入仍能读取，新的状态日志输出 `open_questions`。知识条目新增 `supersedes`，用于明确指定被新规则替代的旧知识 ID。

分类由原有学生模型在一次结构化输出中完成。一个教学片段可以同时生成知识、问题和事件；程序检查来源、修订关系和事件数量，不通过关键词猜测语义。

## 三、知识纠正与模型上下文

- 同 ID 更新：保存旧版本到 `knowledge_history`，再更新当前条目。
- 不同 ID 纠正：新条目使用 `supersedes` 指向旧条目；旧条目标为 `conflict`，首次失效时保存旧版本。
- 未完整纠正：允许旧规则先失效，不要求模型猜测尚未讲出的新规则。
- 普通课堂请求通过 `learning_context()` 组织状态：当前 `knowledge` 仅包含 `tentative/understood`，`unclear/conflict` 放入 `inactive_knowledge`，历史记录单独提供。
- 修订历史引用的教师来源继续保留；发送给学生的来源仍使用主干的规范课堂文本，不附带审核原文等审计字段。

原始课堂日志和来源不改写。失效与历史内容仍可供追溯，提示词要求模型遵循后续明确纠正，不能将旧记录继续当作有效规则。

## 四、理解和问题状态

| 状态 | 含义 |
|---|---|
| `tentative` | 初步认知 |
| `understood` | 根据课堂行为推断的理解 |
| `unclear` | 缺少必要信息 |
| `conflict` | 冲突或失效 |

`understood` 不代表标准答案或永久掌握，没有 `verified` 状态。教师确认或学生自称理解不会产生经过验证的掌握结论。

问题的 `pending/asked/resolved/deferred` 生命周期、去重、提问次数和发言控制保持原样。已解决问题继续进入模型上下文；程序禁止再次激活已匹配的已解决问题，并拦截对它的候选提问。现有策略也会忽略其后续更新，包括新增解决依据，本次不调整这一行为。

## 五、验证方式

离线测试使用 mock 模型和临时目录，覆盖：

- 知识、课堂事件和问题字段兼容。
- 同 ID 修订、不同 ID 替代、未完整纠正及无效来源的原子拒绝。
- 最近 20 条事件和有效知识分层。
- 普通课堂请求保留历史来源，同时过滤审核审计字段。
- 开启和关闭语音审核时的文字课堂协议：学习、纠正、普通回答、下课事件及结束记录。
- 主干既有的语音审核、音频上传、会话和播报回归。

运行 `.venv/bin/python -m pytest -q`，Windows 使用 `.venv\Scripts\python.exe -m pytest -q`。最新 main 已包含 Windows PCM 参数测试的短名称修复，避免超长参数 ID 触发环境变量长度限制；本分支保留该行为及原独立提交，变基后该提交仅剩说明文档差异。前端脚本另做语法检查，并运行 `scripts/check_model_files.py` 和 `git diff --check`。

`scripts/verify_cognition.py` 是可选的真实模型文字回放：先在本地提供原始日志 `logs/3e206b001729.jsonl`，配置模型服务，启动后台并确保课堂空闲。脚本检查未讲规则、纠正未完成、后续普通回答和结束事件，不再出题或评分。此脚本消耗 API 额度，不属于离线回归，也不验证原始音频的 ASR 效果。

2026-10-09 本地验证：**118 passed、2 skipped、0 failed**。跳过项分别需要真实 ASR 模型和样本、本地 VAD 和语音样本；现有依赖产生一条 Starlette/httpx 弃用提示。模型文件检查、前端脚本语法检查和差异空白检查通过。隔离无头浏览器使用两份对照日志检查新旧状态展示、测验入口移除、上传及审核界面初始化，未出现 JavaScript 错误。没有调用真实模型、麦克风或正在运行的课堂服务；Windows 实机播报和长课堂效果未在本轮实测。

## 六、限制

语义分类、教师纠正的识别和知识边界仍依赖模型。来源校验只能证明来源存在，不能证明语义推导正确；状态分层也不能让预训练模型真正遗忘。长课堂的上下文增长尚未处理，旧日志不迁移或清洗。离线结构与流程测试不能替代真实课堂效果评估。
