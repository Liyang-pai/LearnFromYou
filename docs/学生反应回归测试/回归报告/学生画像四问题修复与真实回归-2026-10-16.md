## 用量与测试安排问题

充值恢复后的本轮，剔除重复合并目录并计入一次连通性检查，共记录 **1411 次请求、1407 次模型输出、4795039 tokens**：输入 4297643、输出 497396。输入中缓存命中 2379264、未命中 1918379。失败请求不算模型输出。这些是 API 返回的用量，不是人民币扣费，实际费用须对照账户账单。

消耗过快的主要原因是测试安排过大且重复：画像矩阵为五题材×三水平×三课型×两次抽样，共90组；每组通常包含候选生成、独立审查、实际前置提取三个请求，另有结构或内容修复。课堂每轮又会发送画像、已讲材料、状态及增长的历史。发现局部问题后仍多次整批重跑，没有控制总调用预算，应由本次执行安排承担责任。

充值后进行了三轮完整矩阵尝试（其中第三轮中断），五套80轮课堂路径，以及课前、年级和局部验证。中间版本存在被内容复核否决的结果，不能把这些调用合并成一个通过率。加上充值前的既有记录，累计为3221次请求、3155次模型输出、8098253 tokens。逐批明细、Prompt阶段哈希和当前文件哈希见[本轮清单](../../logs/profile-resume-20261016-manifest/summary.json)。

## 修改范围及原因

主要修改了 `backend/prompts.py`：年级映射与优先级、五题材前置边界、水平与课型区别、逐条知识审查、内容修正、课前提取覆盖，以及学生课堂中直接任务识别、未知知识边界、条件推理和学习回顾要求。

没有停在只改 Prompt：多轮仅改 Prompt 后仍复现答案进入已有知识或“未知”栏目。随后添加必要的服务端约束：

1. `backend/student_profile.py`：候选生成后，独立请求逐条分类，只保留合法前置；后三段使用受限的任务、支持和缺口描述，隔离自由生成答案。最多一次内容修正，总时限仍为90秒；不返回未通过校验的结果。
2. 同文件补年级完整别名映射；教师年级、学科、知识点完整保留。知识点留空时以主题原文作为安全目标标签，避免自动展开成定义或公式。这比原先自动展开知识点更保守。
3. `backend/schemas.py`：明确逐行已知不仅要逐字引用，还必须全部覆盖；遗漏进入现有结构修复。
4. `backend/llm.py`：画像审查与修正阶段沿用画像阶段的超时和错误处理。
5. 更新两份本地测试，新增 `tests/live_profile_regression.py` 保存真实设置、模型请求输出、实际初始化、课堂送达及用量证据。

接口仍接收原7个设置字段、返回原4个画像字段；没有修改前端交互，没有提交或部署。用户原有文档保留。

## 仍需处理的内容

- **画像审查可靠性**：称量范围与仪器量程混淆曾通过；最新Prompt已补拒绝规则，真实验证遇402。旧批次的简单方程求解/检验泄漏已补强Prompt，新完成样本未再检出该类操作声明，但不能由此保证所有随机生成均正确。
- **符号歧义**：“电流表示电流强弱，单位是安培，符号A。”可被理解为单位符号，也可能误读为量符号，应明确区分，保留待复核。
- **课堂来源边界**：密度C7在只需说明缺体积时扩展到排水法，该方法没有明确来源；欧姆定律C6仍把电压不变写成某结果成立的“必须”条件，存在推断过强风险。没有把61次回复送达统计成61次语义全部通过。
- **覆盖限制**：未测浏览器点击、语音/ASR、完整正常教学路径A或任意题材的稳定性。

当前不继续调用API。后续若用户要求继续，应先使用已有失败例及少量针对性样本验证，明确总调用上限后再决定是否扩到整批；不重复当前的多轮全量重跑方式。
