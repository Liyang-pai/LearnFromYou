# 五状态知识状态机实施说明

2026-10-14，依据《LearnFromYou-最终状态机架构》实施，状态结构版本为 `2`。问题生命周期、转写审核与独立教学报告继续使用各自流程；教学报告仍评价实际讲授，学生认知不代表教师正确性。

## 状态与使用限制

| 状态 | 前端名称 | 判定与使用 |
| --- | --- | --- |
| `understood` | 课堂推断理解 | 具有充分理解依据，可以推理；不等于事实已经外部验证或永久掌握 |
| `tentative` | 推断待确认 | 可补出的跳步，或依赖未确认前提；条件性使用并传递待确认性质 |
| `unclear` | 理解障碍 | 缺少建立理解链条的关键依据；记录障碍，可通过其他合理路径重新判定 |
| `conflict` | 矛盾待解决 | 学生能识别同条件矛盾；双方相关独立条目都暂停作确定前提 |
| `invalid` | 已失效 | 教师明确撤回、纠正或替代的旧条目停止使用，保留历史 |

先将知识拆成可独立修订的结论，分别记录条件。局部矛盾或纠正不影响无关结论。仅说“应该是另一种规则”不自动表示撤回；“先不谈图像，换表格讲”也不是失效依据。没有新证据时不因问题关闭、重复讲解或学生自己的发言自动升级。

## 数据及提交

- `Knowledge` 保存 `text`、`conditions`、`status`、`reason`、`sources`、`revision` 和 `dependencies`。依赖引用具体 ID 与修订号。
- 画像摘录的 `p` 条目初始为 `understood`，原因是“画像确认基础”。原始画像和来源保留，课堂上下文中的有效基础服从修订后的认知。
- `conflicts` 保存双方、条件、来源、矛盾说明及解决依据。教师澄清不同条件后可分别重新判定；明确撤回一方会解除该关系，但另一方仍需重新判定。
- 明确纠正需 `correction_sources` 引用当前教师证据并定位旧条目。同 ID 纠正通过 `knowledge_history.previous` 保留当时状态，并用 `invalidated` 标记旧版本失效；不同 ID 用 `supersedes` 将旧条目置为 `invalid`。已失效条目不能恢复，重新采用须新建 ID。
- 获得独立解释后，移除不再使用的旧依赖需 `independent_sources` 引用相应教师证据；不能只因前提失效而删依赖。没有独立解释的结论保留依赖并转为理解障碍。
- 整轮在副本上预校验来源、冲突双方、依赖版本、自依赖和循环；知识、问题、事件全部通过后一次提交。内容、状态、条件或依赖变化递增知识修订号；仅依据说明变化保留历史但不触发下游复核。

语义判断由模型提出，程序校验关联、传播未确认性质并执行使用限制。来源存在不能证明引用内容在语义上足够支持结论。

## 内部依赖复核

课堂调用首先处理受影响结论，未处理部分进入 `pending_reviews`；它是队列标记，不是第六种状态。课堂上下文分开提供确定知识、待确认知识、不可用知识、冲突、历史和复核队列。候选回复在生成后与实际发言前均检查其声明使用的知识。

内部复核按依赖顺序每批最多 16 个目标，按当前目标及依赖版本去重，只更新认知，不生成发言、问题或课堂事件。沿用模型客户端的两次总请求预算（首次生成加一次结构/关联修复，未超过两次修复上限）；连接失败不自动反复重试。新教师输入优先，正在运行的复核提交前比对课堂输入修订与整体状态版本；过期结果丢弃，由当前状态队列重新安排。

复核失败时保留使用限制，页面显示可重试提示，教师可继续输入；无关新内容不自动重试失败目标。结束课堂沿用最长 100 秒收尾等待，未完成项随 `finished.unreviewed_knowledge` 保存。关闭课堂后不继续运行后台复核。

## 实施位置与兼容

- `backend/cognition.py`：原子更新副本中的知识、冲突、修订与依赖传递。
- `backend/schemas.py`、`backend/prompts.py`：输出结构、五状态依据及内部复核提示词。
- `backend/session.py`、`backend/policy.py`：上下文、调度、过期检查、失败重试和发言限制。
- `frontend/app.js`、`frontend/style.css`：五状态、依据、依赖、冲突对象、失效历史及复核提示。

旧日志无需迁移，缺少新增字段仍可展示；历史 `conflict` 原样读取，不推测它当时是否应为 `invalid`。原始课堂日志追加记录，不回写历史事件。模型密钥及真实验收日志不提交。

真实模型使用项目现有配置，八组案例最新一次均通过：

| 案例 | 核对的路径 |
| --- | --- |
| 超前内容 | 缺少函数与坐标基础时记录 `unclear` 及具体障碍 |
| 完整讲解 | 已有基础支持完整定义，得到 `understood` |
| 可补跳步 | 可补出的中间计算保留 `tentative` |
| 画像矛盾 | 新规则与 `p` 知识关联冲突，原画像规则也暂停使用 |
| 条件澄清 | 红盒、蓝盒条件分开，解除冲突并保留两种规则 |
| 教师纠错 | 明确撤回旧规则，保留失效历史，后续按新规则回答 |
| 多路径理解 | 表格建立局部理解，同时保留图像理解障碍 |
| 依赖传播与失效 | 待确认前提向下传递；前提撤回后保留依赖及理解障碍 |

本次共计 44 次请求尝试，包含网络失败与结构修复，未超过 48 次上限。早期失败记录保留；根据暴露的误判补充了矛盾与纠正的区别、换讲法的边界及依赖删除校验，再重验失败案例。记录位于本机 `logs/knowledge-machine-live-20261014/`，包含来源、状态、逐条依据、依赖和复核事件，不纳入 Git。
