日期：2026-10-17（Asia/Shanghai）。版本：第一版历史设计。当前推荐审阅[小纸原图版](../v2-xiaozhi/README.md)，本版保留设计过程。

打开 [index.html](index.html) 浏览全部缩略图，点击任意页面查看原尺寸 PNG；所有图片在 [png/](png/)。可直接把 PNG 发给队友讨论。

## 本次明确要求

- 以用户提供的蓝白色基础设计为依据；“学生状态”导航统一改为“我的教室”。
- 保留原调试前端，正式实现时将正式入口设为 `/`，调试入口为 `/debug`。本轮未改路由。
- 吉祥物与聊天头像仅预留位置和比例，不绘制临时角色，也不使用其他角色代替；现有纸片图形仅作为无面部的几何品牌占位。
- 首页不保留划掉的“体验示例课堂”，不增加账号、通知、排行、分数、虚构课程历史等独立系统。
- **用户追加的覆盖标准：调试前端除上传录音、内部信息的来源编号与引用/依赖关联展示之外，其他功能与信息必须在正式前端有入口。**
- 调试前端保留上传录音和内部关联展示；正式前端移除这两类内容。转写正文、审核结果、认知状态、问题、模型输入输出与诊断能力继续提供。
- 先给用户看 PNG，再由用户决定实施范围；当前没有产品实现、服务启动、Git 提交、推送或真实模型测试授权。

## 视觉与信息组织

浅蓝白色、深蓝标题、清楚的中文标签和低对比度辅助线保持一致。首页突出一个主要动作；“我的教室”中央留给吉祥物和最新回应，右侧提供对话；更完整的信息放入始终可达的“课堂详情”，避免丢失能力或把所有技术信息挤进主舞台。

报告不打分，突出一个最值得改进的点、可直接使用的讲法和下一次独立练习。麦克风、学生发言、学生播报与中央字幕分别控制。

## 已有能力与新增建议的边界

已有后端仍按当前源码运行，`/` 仍是原调试界面，尚未增加 `/debug`。画像、课堂 WebSocket、截图、ASR 管理与报告的既有 API 已在本轮只读核对。

以下属于设计建议，需要后续明确实现：正式页面导航与布局、主页、课堂详情的信息整理和脱敏展示/导出、吉祥物嵌入协议、网页端编辑/保存 API 配置与测试连接、输入设备选择、课堂偏好默认值持久化、统一诊断导出与路由迁移。当前模型配置主要来自后端 `.env`；图中的“保存设置”不代表现有服务已经支持这个接口。

未设计课程历史/跨课堂记忆、账号体系、多个活动课堂、教学分数或自动模型调用。所有模型状态、请求耗时、tokens、进度条、时间、报告与课堂文字都是示例。

## 产物与复核

- `png/`：42 张独立 PNG，均为 1920 × 1200。
- `overview/`：5 张总览 PNG，以及生成总览的本地 HTML。
- `index.html`：本地图片图册，仅链接静态图片，无网络请求、服务或模型调用。
- `html/`：生成 PNG 的静态画面源文件，不含业务行为，不应直接复制为正式前端。
- `source/build.cjs`：设计出图脚本，离线启动无头浏览器进行本地文件排版和截图；依赖和运行方式见[总入口](../README.md#出图源码与复核)。
- `source/verify.cjs`：图片完整解码、页面范围、排除项、弹窗与图册加载检查。
- `manifest.json`、`verification.json`：尺寸、SHA-256、版面检查与最终复核记录。
